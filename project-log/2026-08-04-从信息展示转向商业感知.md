# 从信息展示转向商业感知

日期：2026-08-04

## 用户问题

Daily Digest 缓解了错过新信息的焦虑，但大量短、散、互不关联且不能直接产生效果的信息，把综合判断的工作转嫁给用户，形成新的认知负担。

## 现状证据

- 首页此前默认展示想法墓地，而不是外部世界变化或商业判断。
- 2026-08-04 熵减页同时展示 3 个案例、认知卡、健康提醒、9 条得到课程信号和昨日想法回顾，多种认知任务并列。
- Browse 当前有 352 条记录、18 个分页；其中大量是内部想法和历史材料，不是当天值得处理的外部变化。
- 页面结构按来源和内部系统分频道，没有负责跨来源关联并形成结论的默认入口。

## 本轮改变

- 新增“商业感知”频道，并将最新 Repricing 报告设为首页。
- 首页只默认展开一个主判断；候选 Repricing 判断和证据层默认收起。
- 将“随便逛逛”重新命名为“信号库”，明确它是后台证据池而非每日阅读任务。
- 渲染器优先读取 `~/.hermes/data/repricing/reports/YYYY-MM-DD.md`，在尚无正式报告时读取 10x 项目中的 Repricing 试跑报告。
- 修正导航：想法墓地拥有独立频道路径；手机端导航改为单行横向滚动，避免六个频道堆成多行。
- 页脚改为“先形成判断，再占用注意力”。
- 同步更新 `analyze-repricing-signals` Skill，加入注意力合同和 Daily Digest 正式输出路径。

## 关键判断

Daily Digest 不应把“已采集”误当作“值得用户阅读”。采集层可以高召回，用户界面必须高压缩。它的核心产品指标不是信息量、卡片数或新鲜度，而是减少用户从散点形成判断的认知劳动。

默认信息层级应为：一个主判断 → 少量候选判断 → 按需证据 → 原始信号库。没有足够好的判断时，宁可明确写“今天没有值得占用注意力的 Repricing 结论”，也不应用碎片填满页面。

## 验证

- `render.py` 通过 Python 编译检查并成功完成 2026-08-04 渲染。
- 实际生成首页和 `perception/2026-08-04.html`，主判断为“企业 AI 的行动资格正在被重新定价”。
- 浏览器桌面与 390×844 手机宽度检查均无横向页面溢出。
- 手机端导航高度由多行状态的约 166px 降到约 99px；六个频道改为横向滚动。
- 首页共 3 张卡片，只有主判断默认展开，候选判断与证据层收起。

## 风险与下一步

- 当前首页使用的是一次试跑报告；还没有稳定的每日 Repricing 生成任务。
- 报告质量仍取决于分析本身。把首页改漂亮不能替代高质量外部信号与大胆求证。
- 需要连续试跑，观察真正有洞见的日子、无结论的日子以及用户是否会主动展开证据，再决定是否继续调整。
