# Daily Digest 定时发布切换个人站

## 目标与背景

用户要求把原先定时发布到 GitHub Pages 的任务改为定时发布到个人站 `jsbuildslowly.com/digest/`。

## 实际运行链确认

- 每天 8:00 的 Hermes 任务 `d02122a151d5` 调用 `browse_radar_pipeline.sh`，此前最后一步直接提交并推送 Daily Digest 仓库。
- 每天 9:00 的 Hermes 任务 `a9cf36ac90bb` 调用 `entropy_plan.py`，此前在渲染后直接推送并宣称部署到 GitHub Pages。
- `deploy.sh`、`deploy_daily_digest.sh` 与 `publish_dual_innovation.sh` 是同类备用或专项发布入口。

## 架构调整

- 新增统一入口 `publish_to_personal_site.sh`：渲染公开内容、保留 Git 版本记录、推送后立即触发 `JoeyShee/jsbuildslowly-site` 的 Cloudflare Pages 工作流，并等待部署成功。
- 8:00、9:00 与备用发布入口全部改为调用统一入口，避免某个旧脚本继续把 GitHub Pages 当正式终点。
- 个人站原有每小时同步继续作为失败兜底；正常定时任务不再等待整点，会在内容生成后立即发布。
- GitHub 仓库仍保存公开产物历史并作为个人站只读来源，不新增跨仓库写入 Token，也不接触私人素材。

## 旧地址兼容

- 新增 `docs/index.html` 与 `docs/404.html`，用于把旧 GitHub Pages 首页和历史路径跳转到个人站对应 `/digest/` 路径。
- 验证个人站直发链后，将 GitHub Pages 发布目录从仓库根目录切换到 `/docs`；旧链接可继续抵达新站，但 GitHub Pages 不再承载正式内容。

## 本地验证

- 所有 Shell 入口通过语法检查。
- Hermes 正在运行的 `entropy_plan.py` 及其兼容副本通过 Python 编译检查。
- 统一入口完成真实发布：Daily Digest 提交 `3014067` 推送后直接触发个人站 workflow run `31373216287`，Cloudflare Pages 构建和部署成功。
- 无内容变化时统一入口返回 `[SILENT]`，不会制造重复部署。
- GitHub Pages 已从仓库根目录切换到 `/docs`；首页返回迁移页，历史路径由 404 兼容页在浏览器中映射到个人站对应路径。
- `jsbuildslowly.com/digest/` 与当天熵减页面公网可访问；GitHub 仓库不再是正式阅读出口。
- 发布失败会向上传递为定时任务失败，不再只打印错误后仍把 cron 标记为成功。

## 最终边界

- GitHub 只保留公开产物版本历史和个人站只读同步源。
- 定时任务的完成标准改为个人站 Cloudflare 部署成功。
- 个人站每小时同步继续保留为兜底，但正常发布会在 8:00、9:00 等内容任务结束后立即触发。
